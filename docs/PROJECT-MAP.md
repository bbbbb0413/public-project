# 코드 지도
## 저장소 구조 규약
- `front` (`public-front`) — React 19 + Vite + TypeScript 기반 SPA. `src/api/`에 백엔드 게이트웨이 REST·SSE 통신 모듈을 두고, `src/components/`(일반 화면 및 `ai/`, `admin/` 하위 도메인)에 UI 컴포넌트를 배치한다. 전역 인증 상태는 `src/context/`에서 관리하며, 실시간 채팅 WebSocket 연결은 `src/hooks/useChatSocket.ts`와 `src/flatbuffers/`(FlatBuffers 직렬화)가 담당한다.
- `python-server` (`public-python-server`) — FastAPI 기반 AI 마이크로서비스(`src/ai_service/`). 진입점 `main.py` 아래 도메인별 디렉토리(`rag/`, `knowledge/`, `llm_gateway/`, `prompt/`, `feedback/`, `observability/`)마다 `router.py`(HTTP 입구), `service.py` 또는 `application/*_use_case.py`(로직), `repository.py`(MongoDB·Qdrant·Redis 저장), `schemas.py`(도메인 모델 및 계약), `dependencies.py`(DI)를 둔다. Kafka 이벤트 소비자는 `infrastructure/messaging/*_consumer.py`에 모이며, 각 도메인 하위 `domain/*`, `presentation/`, `infrastructure/persistence/` 등의 빈 디렉토리는 계층 단순화 리팩터링 과정에서 남은 흔적이다.
- `server` (`public-server`) — NestJS 모노레포(`apps/*`, `libs/*`). 외부 HTTP·SSE·WebSocket 요청은 `apps/gateway`가 단독 진입점으로 받아 내부 마이크로서비스(`apps/identity`, `apps/payment`, `apps/chat-service`, `apps/admin-server`)에 gRPC(`*.grpc-controller.ts`)로 위임하거나, `apps/gateway/src/ai/proxy/*-proxy.controller.ts`를 통해 `public-python-server`로 HTTP 프록시한다. 공통 인증(`libs/auth`), gRPC·FlatBuffers 계약(`libs/rpc`), DB·로깅·예외 처리(`libs/common`)는 `libs/`에 모이며, `apps/ai-service`는 Python 서버로 이관되기 전의 레거시 NestJS AI 애플리케이션이다.

## 아쉬운 곳
- **AI 답변 참고 문서 원문 보기 시 팝업 차단 및 빈 탭 잔류 결함이 발생하고, 에러 상태가 전역으로 오염된다** — `public-front/src/components/AiService.tsx:361-381` (`handleViewSourceFile`), `public-front/src/components/AiService.tsx:166` (`fileViewError`), `public-front/src/components/AiService.tsx:1690-1694, 1835-1839` (`AiService`). 비동기 파일 다운로드(`getDocumentFile`)에 앞서 `window.open('', '_blank')`로 빈 탭을 사전 생성하여 브라우저의 비동기 팝업 차단 정책에 걸리거나, 백그라운드 다운로드 실행 후 `about:blank` 빈 탭이 브라우저에 영구 잔류한다. 또한 원문 파일 다운로드 실패 시 `fileViewError`가 단일 문자열 전역 상태로 관리되어, 하나의 출처 문서에서 오류가 발생하면 화면의 모든 AI 메시지 버블 및 스트리밍 영역 하단에 "원본 파일을 불러오는 데 실패했습니다." 에러가 일괄 노출된다.
- **답변 평가(피드백) 시 불만족 사유 빠른 선택과 재질문 연계가 부재하며, 에러 버블 발생 시 턴 인덱스가 어긋나 404가 발생한다** — `public-front/src/components/AnswerFeedback.tsx:85-133` (`AnswerFeedback`), `public-front/src/components/AiService.tsx:404-413, 811-819, 1721-1722` (`handleSubmitFeedback`, `startQuestionStreaming`, `AiService`), `public-python-server/src/ai_service/feedback/service.py:61-71` (`FeedbackService._assert_answer_is_readable`). 정확도가 낮을 때(1~2점) 불만족 사유(환각, 출처 상이 등)를 선택할 수단이 긴 텍스트 입력창 하나뿐이라 피드백 정형화가 어렵다. 평가 제출 후 직전 질문을 복원하여 보완 재질문하는 액션 연계가 없으며, 스트리밍 에러 버블(`isError: true`)이 `chatLog`에 추가되면 배열 인덱스 `idx`가 백엔드 세션 턴 인덱스보다 커져 평가 제출 시 `turn_index >= len(turns)` 조건에 걸려 404 에러가 발생한다.
- **AI 답변 참고 문서(출처)의 청크 번호 표기가 불일치하고, 대화창 내 청크 열람 모달 진입점이 부재하다** — `public-front/src/components/AiService.tsx:1666, 1811` (`AiService`), `public-python-server/src/ai_service/rag/application/ask_use_case.py:177` (`AskUseCase._build_rag_messages`), `public-front/src/components/AiService.tsx:665-685, 1963-2002` (`handleOpenChunks`, `chunks-modal`). 답변 버블 참고 문서에서는 `청크 {chunk.chunkIndex}`(0-based)로 표기되지만 백엔드 LLM 컨텍스트는 `섹션 {chunk_index + 1}`(1-based)을 주입하고 지식베이스 관리 모달에서도 `청크 #{chunk.chunkIndex + 1}`(1-based)을 사용하여 사용자가 근거를 대조할 때 혼란이 발생한다. 또한 답변 버블에는 300자 축약 스니펫만 제공되어 전체 문맥을 보려면 대용량 원본 파일 전체를 열어야 하며, 지식베이스 관리 테이블(`doc-table`)에 이미 구현된 청크 모달을 대화 버블에서 직접 열 수 있는 진입점이 없다.
- **게임 유저 로그인·회원가입 토큰에 계정 ID(`id`)가 누락되어 모든 유저가 `accountId = 0`으로 결제 내역을 공유한다** — `public-server/apps/gateway/src/identity/identity-gateway.controller.ts:59-63, 81-85` (`IdentityGatewayController.login`, `register`), `public-server/apps/gateway/src/auth/gateway-auth.guard.ts:67-72` (`GatewayAuthGuard.canActivate`), `public-server/apps/gateway/src/payment/payment-gateway.controller.ts:51, 76, 95` (`createPayment`, `listPayments`, `getPayment`). 로그인/회원가입 응답 본문에는 `accountId: Number(reply.id)`를 반환하지만 정작 JWT 토큰 페이로드(`makeAuthToken`)에는 `id`를 넣지 않는다. 이로 인해 인증 가드가 세션 생성 시 `gameDbId: user.id ?? 0`으로 항상 `0`을 주입하여, 모든 게임 유저의 결제 생성 및 조회가 `accountId: 0`으로 위임되는 치명적인 계정 간 결제 데이터 오염이 발생한다.
- **실시간 채팅에서 이전 대화 페이징 기능 및 소켓 이벤트가 부재하다** — `public-server/apps/gateway/src/chat/chat-gateway.gateway.ts:96-127, 217` (`ChatGateway`), `public-front/src/components/ChatRoom.tsx:14-110` (`ChatRoom`), `public-front/src/hooks/useChatSocket.ts:47-64` (`useChatSocket`), `public-server/apps/chat-service/src/message/rpc/chat.grpc-controller.ts:47-54` (`ChatGrpcController.getMessages`). `chat-service`의 gRPC에는 `beforeTimestamp` 기반 메시지 조회가 지원되지만, 게이트웨이 WebSocket에는 과거 메시지를 페이징 요청하는 소켓 이벤트(`fetch_history` 등)가 없어 `join_room` 시점의 최근 20개 메시지만 수신된다. 프론트엔드(`ChatRoom`, `useChatSocket`)에도 과거 대화 더보기 UI나 스크롤 페이징 로직이 전혀 없어 과거 대화를 불러올 수 없다.
