# 코드 지도
## 저장소 구조 규약
- `front` (`public-front`) — React 19 + Vite + TypeScript 기반 SPA. `src/api/`에 백엔드 게이트웨이 REST·SSE 통신 모듈을 두고, `src/components/`(일반 화면 및 `ai/`, `admin/` 하위 도메인)에 UI 컴포넌트를 배치한다. 전역 인증 상태는 `src/context/`에서 관리하며, 실시간 채팅 WebSocket 연결은 `src/hooks/useChatSocket.ts`와 `src/flatbuffers/`(FlatBuffers 직렬화)가 담당한다.
- `python-server` (`public-python-server`) — FastAPI 기반 AI 마이크로서비스(`src/ai_service/`). 진입점 `main.py` 아래 도메인별 디렉토리(`rag/`, `knowledge/`, `llm_gateway/`, `prompt/`, `feedback/`, `observability/`)마다 `router.py`(HTTP 입구), `service.py` 또는 `application/*_use_case.py`(로직), `repository.py`(MongoDB·Qdrant·Redis 저장), `schemas.py`(도메인 모델 및 계약), `dependencies.py`(DI)를 둔다. Kafka 이벤트 소비자는 `infrastructure/messaging/*_consumer.py`에 모이며, 각 도메인 하위 `domain/*`, `presentation/`, `infrastructure/persistence/` 등의 빈 디렉토리는 계층 단순화 리팩터링 과정에서 남은 흔적이다.
- `server` (`public-server`) — NestJS 모노레포(`apps/*`, `libs/*`). 외부 HTTP·SSE·WebSocket 요청은 `apps/gateway`가 단독 진입점으로 받아 내부 마이크로서비스(`apps/identity`, `apps/payment`, `apps/chat-service`, `apps/admin-server`)에 gRPC(`*.grpc-controller.ts`)로 위임하거나, `apps/gateway/src/ai/proxy/*-proxy.controller.ts`를 통해 `public-python-server`로 HTTP 프록시한다. 공통 인증(`libs/auth`), gRPC·FlatBuffers 계약(`libs/rpc`), DB·로깅·예외 처리(`libs/common`)는 `libs/`에 모이며, `apps/ai-service`는 Python 서버로 이관되기 전의 레거시 NestJS AI 애플리케이션이다.

## 아쉬운 곳
- **답변 평가(피드백) 시 불만족 사유를 빠르게 선택할 수 없고 재질문 연계가 없으며, 에러 버블 발생 시 턴 인덱스가 어긋나 404가 발생한다** — `public-front/src/components/AnswerFeedback.tsx:85-133` (`AnswerFeedback`), `public-front/src/components/AiService.tsx:404-413, 811-819, 1672-1679` (`handleSubmitFeedback`, `startQuestionStreaming`, `AiService`), `public-python-server/src/ai_service/feedback/service.py:61-71` (`FeedbackService._assert_answer_is_readable`). 정확도가 낮을 때(1~2점) 왜 틀렸는지(환각, 출처 상이 등)를 입력할 수단이 긴 텍스트 필드 하나뿐이라 피드백 정형화가 어렵다. 평가 제출 후 직전 질문을 복원하여 보완 재질문하는 액션이 없으며, 인라인 에러 메시지가 `chatLog`에 포함될 경우 배열 인덱스가 백엔드 세션 턴 수보다 커져 피드백 제출 시 404 에러가 발생한다.
- **신뢰도가 낮은(60% 미만) 답변에 주의 경고 배너 및 질문 구체화 유도가 부재하다** — `public-front/src/components/AiService.tsx:1490-1506` (`AiService`). 검색 출처가 아예 없는 경우(`isNoSources && (msg.confidence === 0 || missing)`)에만 `[근거 문서 미발견 (모델 일반 지식 기반 답변)]` 경고 배너가 표시되며, 관련도가 낮은 청크만 검색되었거나 비평 검증을 미달하여 신뢰도가 60% 미만(`msg.confidence < 0.6`)인 답변은 상단 경고가 뜨지 않는다. 하단 메타 영역에 작은 빨간 배지만 붙을 뿐이며, 질문을 복원하거나 구체화할 수 있는 인터랙션이 전혀 없어 사용자가 환각 정보를 사실로 오인하기 쉽다.
- **게임 유저 로그인·회원가입 토큰에 계정 ID(`id`)가 누락되어 모든 유저가 `accountId = 0`으로 결제 내역을 공유한다** — `public-server/apps/gateway/src/identity/identity-gateway.controller.ts:59-63, 81-85` (`IdentityGatewayController.login`, `register`), `public-server/apps/gateway/src/auth/gateway-auth.guard.ts:67-72` (`GatewayAuthGuard.canActivate`), `public-server/apps/gateway/src/payment/payment-gateway.controller.ts:51, 76, 89` (`createPayment`, `listPayments`, `getPayment`). JWT 토큰 페이로드에 `id: Number(reply.id)`를 포함하지 않아 게이트웨이 인증 가드가 세션 생성 시 `gameDbId`를 항상 `0`으로 세팅한다. 이로 인해 모든 게임 유저의 결제 요청 및 결제 내역 조회가 `accountId: 0`으로 위임되어 치명적인 계정 간 결제 데이터 오염이 발생한다.
- **실시간 채팅에서 발신자 닉네임이 전달·저장되지 않아 화면에 UUID가 노출되고 이전 대화 페이징이 불가능하다** — `public-server/apps/gateway/src/chat/chat-gateway.gateway.ts:247-254` (`handleSendMessage`), `public-server/apps/chat-service/src/message/rpc/chat.grpc-mapper.ts:13-35` (`ChatGrpcMapper.toMessageBuffer`, `toGetMessagesResponse`), `public-front/src/components/ChatRoom.tsx:85` (`msg.senderId`), `public-server/apps/chat-service/src/message/rpc/chat.grpc-controller.ts:47-51` (`ChatGrpcController.getMessages`). 게이트웨이와 gRPC 매퍼에서 `nickName`을 전달하지 않아 채팅방 화면에 닉네임 대신 긴 UUID 문자열이 렌더링된다. 또한 gRPC 컨트롤러가 이전 대화 조회 시 요청받은 `request.before` 커서 대신 현재 시간(`Date.now() * 1000`)으로 하드코딩 조회하여 이전 대화 불러오기가 불가능하다.
- **결제 시스템에 결제 취소·환불 도메인 로직 및 상태가 전무하여 되돌릴 수 없는 결제만 존재한다** — `public-server/apps/payment/src/payment/domain/model/payment-status.enum.ts:1-5` (`PaymentStatus`), `public-server/apps/payment/src/payment/application/create-payment.use-case.ts:27-94` (`CreatePaymentUseCase`), `public-front/src/components/PaymentHistory.tsx:16-95` (`PaymentHistory`). 결제 도메인 모델에 `CANCELLED` 또는 `REFUNDED` 상태가 아예 정의되어 있지 않으며 취소·환불 유스케이스가 부재하다. 결제 내역 화면에서도 결제 완료 건에 대한 취소 요청 UI가 없어 한번 승인된 결제는 시스템상 되돌릴 방법이 없다.
