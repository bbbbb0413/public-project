## 배경 / 문제

금액을 문자열로 만드는 코드가 화면과 응답마다 흩어져 있어 표기가 제각각이다.
어떤 곳은 `1234567원`, 어떤 곳은 `1,234,567 원` 처럼 나온다.

한 곳에서 규칙을 정하고 백엔드와 프론트가 같은 규칙을 쓰게 한다.

## 요구사항

- [ ] 백엔드에 원화 금액을 문자열로 바꾸는 함수를 추가한다
- [ ] 프론트에도 같은 규칙의 함수를 추가한다
- [ ] 두 구현이 같은 입력에 같은 결과를 낸다

## 비요구사항 (Out of scope)

- 기존 코드의 금액 표기를 찾아 바꾸는 작업은 하지 않는다. 함수만 추가한다.
- 다른 통화는 다루지 않는다.
- 백엔드와 프론트가 코드를 공유하게 만들지 않는다. 각자 구현한다.

## 규칙

두 구현이 반드시 지켜야 할 것:

| 입력 | 출력 |
|---|---|
| `1234567` | `"1,234,567원"` |
| `1000` | `"1,000원"` |
| `999` | `"999원"` |
| `0` | `"0원"` |
| `-1234` | `"-1,234원"` |
| `1234.7` | `"1,234원"` (소수점 이하 버림) |
| `-0.5` | `"0원"` (`"-0원"` 이 되면 안 된다) |

## 백엔드

`public-server` 의 공용 유틸에 추가한다.

- 위치는 기존 유틸이 있는 곳의 관습을 따른다 (`libs/common/src/utils/` 참고)
- 함수 이름은 `formatWon`
- 시그니처: `formatWon(amount: number): string`
- 테스트도 함께 작성한다. 기존 유틸 테스트의 관습을 따른다.

## 프론트엔드

`public-front` 에 같은 규칙의 함수를 추가한다.

- 백엔드 단계가 먼저 실행되므로, **백엔드가 실제로 어떻게 구현했는지 요약을 보고
  같은 규칙을 따른다.** 위 표와 다르게 구현되었다면 실제 구현 쪽에 맞춘다.
- 함수 이름은 `formatWon`
- 테스트도 함께 작성한다. 기존 테스트는 소스 파일 옆에 `*.test.ts(x)` 로 둔다.

## 수용 기준 (Acceptance Criteria)

- Given `1234567` 을 When 백엔드 `formatWon` 에 넘기면 Then `"1,234,567원"` 이 반환된다
- Given `1234567` 을 When 프론트 `formatWon` 에 넘기면 Then `"1,234,567원"` 이 반환된다
- Given `0` 을 When 양쪽 `formatWon` 에 넘기면 Then 둘 다 `"0원"` 이 반환된다
- Given `-1234` 를 When 양쪽 `formatWon` 에 넘기면 Then 둘 다 `"-1,234원"` 이 반환된다
- Given `1234.7` 을 When 양쪽 `formatWon` 에 넘기면 Then 둘 다 `"1,234원"` 이 반환된다
- Given `-0.5` 를 When 양쪽 `formatWon` 에 넘기면 Then 둘 다 `"0원"` 이 반환된다

## 참고

- 프론트 테스트 설정: `public-front/vite.config.ts` (vitest, jsdom)
