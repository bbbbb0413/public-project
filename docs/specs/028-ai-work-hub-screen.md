## 출처
명세서 "4. 직관적 웹 인터페이스" 중 **4.1 AI 작업 허브 화면**.

## 배경
이 기능은 새 API가 필요한 게 아니라 **정보구조(IA) 자체를 바꾸는** 작업이다. 지금은 질문/업로드/설정이 이미 다 동작하지만, 명세서가 말하는 "허브에서 각 기능으로 이동 + 작업 상태 한눈에 보기" 구조가 아니라 "한 화면에 다 몰아넣은" 구조다.

## 현재 구현 상태 (조사 결과)

| 항목 | 상태 | 근거 |
|---|---|---|
| 허브(진입점 모음) 화면 | ❌ 미구현 | `Profile.tsx`(`src/components/Profile.tsx:11,60-83`)가 `mail/shop/chat/ai` 4개 탭으로 나뉘고, "ai" 탭 하나에 `AiService.tsx`(963줄)가 업로드/질문·채팅/세션 목록/프롬프트 설정을 전부 한 화면에 담고 있음(`AiService.tsx:49-79`의 상태값 개수가 이를 보여줌) |
| 작업 상태(진행중/완료/실패/취소) 통합 뷰 | ❌ 미구현 | 업로드 진행률은 문서 목록에서, 질문 진행 상태(`currentProgress`)는 채팅창에서 각각 따로 표시 — 통합 대시보드 없음 |
| 모바일 반응형 | 🟡 부분구현(CSS 레벨) | `AiService.css`에 `@media (max-width: 900px)`(40행), `@media (max-width: 640px)`(942행) 브레이크포인트 존재. 실제 모바일 파일 업로드 등 기능 동작은 이번 조사에서 검증 못함 — 별도 확인 필요 |

## 명세서와 현재 구현 간 상충 / 차이
1. **"허브 → 각 기능으로 이동" vs "한 화면에 전부"**: 지금 구조를 완전히 허브형으로 바꾸면 `AiService.tsx` 963줄을 여러 화면/라우트로 쪼개는 큰 리팩터링이 된다. 반대로 "허브"를 엄격한 내비게이션 구조가 아니라 "한 화면 안에서도 각 섹션 진입점과 상태 요약이 상단에 잘 보이면 충분"으로 완화 해석할 수도 있다 — 착수 전에 범위를 확정해야 작업량이 크게 달라진다.
2. **이 프로젝트는 SPA + CSR이고 React Router가 없다**(이전 대화에서 확인). 진짜 "화면 간 이동"을 만들려면 지금처럼 `useState` 기반 탭 전환을 유지할지, React Router를 새로 도입할지도 결정해야 한다 — 결제 화면([[020-payment-confirmation-status-handling]])에서 이미 `useState` 기반 탭 분리 패턴을 쓴 적이 있으니, 같은 패턴(라이브러리 추가 없이 탭 전환)으로 충분할 가능성이 높다.
3. **작업 유형이 이질적**: "질문 작업"과 "문서 인제스트 작업"은 상태 모델이 같은 `JobStoreService`([[022-rag-streaming-qa]], [[025-knowledge-document-ingest]] 참고)를 공유하므로, 통합 대시보드를 만들 때 이 공통 스토어를 그대로 조회 소스로 쓸 수 있다 — 새 백엔드 집계 API가 필요할 수도, 프론트에서 두 목록을 합쳐 보여주는 것만으로 충분할 수도 있다.

## 요구사항 (이번 작업 범위)
1. "허브"의 범위를 확정한다 — 완전 별도 화면 라우팅인지, 기존 탭 내부에 진입점+상태 요약 섹션을 추가하는 수준인지.
2. (확정된 범위에 따라) AI 탭 진입 시 질문/업로드/개인설정으로 이동하는 명확한 진입점과, 최근 작업들(질문 작업 + 인제스트 작업)을 상태별로 구분해 보여주는 요약 뷰를 만든다.
3. 모바일 뷰에서 핵심 동작(질문 제출, 파일 업로드)이 실제로 되는지 직접 확인하고, 안 되는 부분을 고친다.

## 비요구사항 (Out of scope)
- 백엔드 AI 처리 로직 변경 — 명세서가 명시적으로 제외.
- 관리자 운영 화면 — 명세서가 명시적으로 제외.
- React Router 등 새 라우팅 라이브러리 도입은, 정말 필요하다고 판단될 때만 최소 범위로.
