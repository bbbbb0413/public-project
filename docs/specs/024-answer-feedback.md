## 출처
명세서 "1. AI 질의응답 경험" 중 **1.3 답변 정확도 평가 및 피드백**(1.3.1 답변 평가 제출). 근거 확인은 [[023-answer-citation]] 참고.

## 배경
이 기능은 완전 신규다. `feedback`/`rating`/`thumbsUp`/`helpful` 등으로 전체 리포를 조사했지만 관련 엔티티·API·UI가 전혀 없다(유일하게 매치된 `AgentPhase`의 "rating" 문자열은 무관한 오탐). 저장소부터 API, 화면까지 전부 새로 설계해야 하는 유일한 항목이다.

## 현재 구현 상태 (조사 결과)
전무. 아래는 새로 만들어야 할 것들의 목록이다.

- 답변 평가 저장소(테이블/컬렉션) — 없음
- 평가 제출/수정 API — 없음
- 사용자별 답변당 평가 1개 유지 + 최신 평가 덮어쓰기 규칙 — 없음
- 프론트 평가 UI(정확도/유용성 선택 + 의견 입력) — 없음

## 명세서와 현재 구현 간 상충 / 차이
직접적인 상충은 없다(비교 대상 자체가 없으므로). 다만 설계 시 참고할 기존 패턴이 있다:
- **저장 위치**: 지금 RAG 세션/메시지는 Python 쪽(`ai_service`)이 MongoDB(`MONGODB_VECTOR_URI`/`MONGODB_DB_NAME: ai_service`)에 저장하는 구조다(`docker-compose.yml`). 평가 데이터도 같은 서비스·같은 DB에 붙이는 게 자연스럽다 — 별도로 NestJS 쪽에 새 도메인을 만들 필요는 없어 보인다. 다만 "답변 평가 제출 이벤트를 기록한다"(명세서 문구, 감사로그 성격)까지 요구하면 Kafka 이벤트 발행이 필요할 수 있다.
- **소유권 검증 패턴**: [[026-admin-approval-and-global-prompt]] 조사에서 개인 프롬프트 소유권 검증 방식(`user_id` 비교)이 이미 있으니 그 패턴을 재사용할 수 있다. 다만 그 조사에서 **같은 종류의 소유권 필터 누락 버그**(다른 사용자 개인 프롬프트가 그대로 노출되는 문제)를 발견했다 — 이 기능을 새로 만들 때 반드시 "본인이 조회 권한을 가진 답변에 대해서만 평가 제출/조회 가능"을 서버 단에서 강제해야 한다(프론트에서 숨기는 것만으로는 불충분, [[026-admin-approval-and-global-prompt]]에 기록된 실제 사례 참고).

## 요구사항 (이번 작업 범위)
1. 답변 평가 데이터 모델을 설계한다: 평가 식별자, 답변(메시지) 식별자, 평가자 식별자, 정확도 값, 유용성 값, 의견(선택), 생성·수정 시각.
2. 평가 제출 API를 추가한다 — 이미 평가한 답변에 다시 제출하면 기존 평가를 갱신(덮어쓰기)한다.
3. 서버 단에서 "본인이 조회 가능한 답변에 대해서만" 평가 제출/조회를 허용하도록 소유권을 검증한다.
4. 프론트: 답변 하단에 정확도/유용성 평가 선택지 + 의견 입력 UI를 추가하고, 이미 평가한 답변에는 본인의 최신 평가를 표시한다.
5. 저장 실패 시 재시도 안내(네트워크 오류 케이스)를 프론트에 넣는다.

## 비요구사항 (Out of scope)
- 관리자가 평가 데이터를 모아보는 대시보드/통계 화면 — 이번 명세서 범위에도 없다.
- AI 모델 재학습이나 평가 결과를 프롬프트/모델에 자동 반영하는 로직.
- 다른 사용자의 평가 상세 열람 — 명세서가 명시적으로 막음.
