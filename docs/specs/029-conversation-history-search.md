## 명세서와 현재 구현 간 상충 / 차이
1. **조회는 절반만 구현됨**: 명세서 수용 기준 3개(시간순 목록 조회 / 키워드 검색 / 답변 보관) 중 첫 번째만 있다. 두 번째(검색)와 세 번째(보관)는 완전 신규다.
2. **목록 항목에 질문 스니펫이 없음**: 명세서는 "최근 질의 일부"를 요구하는데 지금은 `title`만 있다. `title`이 실제로 첫 질문을 요약한 값인지, 별도로 사용자가 짓는 이름인지부터 코드로 확인 필요(라우터 응답 스키마만 봐서는 출처 불명 — 착수 시 `rag/router.py`와 세션 생성 로직을 같이 봐야 함).
3. **검색 범위를 어디까지로 할지 결정 필요**: 명세서는 "제목·질문·답변 기반 검색"을 요구한다. 지금 세션/메시지가 MongoDB에 저장되는 구조([[024-answer-feedback]] 조사에서 확인)라 텍스트 검색을 MongoDB 쿼리로 할지, 별도 검색 인덱스(이미 있는 Qdrant는 벡터 검색용이라 키워드 검색엔 안 맞음)가 필요한지 설계가 필요하다.

## 요구사항 (이번 작업 범위)
1. 세션 목록 응답에 "최근 질의 일부" 스니펫 필드를 추가한다(첫 질문 또는 마지막 질문 앞부분).
2. 세션 목록 조회 API에 검색어 파라미터를 추가하고, 제목·질문·답변 텍스트를 대상으로 검색한다(MongoDB 텍스트 검색 또는 단순 부분일치 — 규모 감안해 단순 구현으로 시작).
3. 답변(또는 세션 전체) 보관 기능을 추가한다: 보관 플래그/컬렉션, 보관 목록 조회 API, 프론트 보관 진입점과 보관함 화면.
4. 프론트 대화 기록 화면에 검색창과 보관함 탭/필터를 추가한다.

## 비요구사항 (Out of scope)
- 팀 간 대화 공유, 공동 편집 — 명세서가 명시적으로 제외.
- 전문 검색 엔진(Elasticsearch 등) 도입 — 지금 데이터 규모에서는 과함, 단순 쿼리로 충분.
